# Work та інструменти Jarvis 0.16

## Запуск

Перемикач Work розташовано у звичайному чаті. Налаштування Work та вибрані паки статей зберігаються окремо для кожного чату. Для нового чату вони переносяться після створення сесії. Статті за замовчуванням вимкнені; null зі старих налаштувань теж означає вимкнений пошук. Користувач явно обирає один або кілька паків, або всі наявні паки. Пункт «Вимкнути статті» очищає вибір. Без вибраних паків Work не отримує knowledge_search; явний @Вікі залишається доступним.

Приклад завдання: «Створи український сайт для викладача співу, адаптуй його до телефона, перевір код і виправ помилки». Агент має створювати справжні файли, виконувати доступні перевірки, аналізувати результати та виправляти знайдене.

## Протокол моделі

Для MamayLM-Gemma-3-4B-IT-v1.0 використовується токенізатор і chat template завантаженого GGUF; застосунок не підміняє їх власним українським токенізатором. Системні інструкції й повідомлення інструментів нормалізуються в ролі, дозволені шаблоном, зі збереженням зображень.

Якщо метадані шаблону не оголошують native tools, модель повертає один JSON-об’єкт за grammar:

```json
{"tool":"workspace","arguments":{"operation":"write_text","path":"project/index.html","content":"<!DOCTYPE html><html lang=\"uk\"><head><meta charset=\"utf-8\"><title>Спів</title></head><body><h1>Уроки співу</h1></body></html>"}}
```

Після виконання хост передає фактичний результат. Завершена відповідь має форму `{"answer":"Відповідь українською"}`. Коли потрібна дія, схема не дозволяє answer. Невідома функція, хибний тип, пропущений обов’язковий аргумент чи невірний enum не доходять до Android. Є одна повторна генерація для виправлення некоректної дії. Сервери без JSON-schema отримують той самий контракт, а перевірка аргументів залишається на стороні хоста.

Моделі зі штатним native tool calling зберігають структурований протокол. Якщо шаблон відхиляється до появи стримінгу, хост може перейти до JSON-протоколу. Дія, яка вже виконувалася, не повторюється через цей механізм.

Основна мова інструкцій — українська. Для Mamay у Work: temperature 0.1, top_k 25, top_p 1, penalty_repeat 1.1, за рекомендаціями основної model card INSAIT. Квантовані версії й інші моделі можуть поводитися по-різному; якість визначають реальні результати перевірок.

## Інструменти

| Інструмент | Алгоритм і критерій успіху |
|---|---|
| workspace | Переглянути наявні файли, прочитати потрібне, створити або змінити повні файли. Відносні шляхи без переходу за межі workspace. read_text підтримує offset/limit. Створення повертає фактичну метаінформацію артефакта. |
| python_exec | Запустити код у локальному Python; stdout/stderr/error і метадані створених файлів повертаються в чат. Для Pillow/PDF/DOCX доступні jarvis_artifacts. Помилка означає потребу виправлення, а не готовий результат. Розширені системні/мережеві дії мають наявне підтвердження застосунку. |
| work_verify | Перевірити всі файли, відомі хосту, та явно вказані тести unittest. Перевірка запускається автоматично перед завершенням, навіть якщо модель забула її викликати. Після змін попередня перевірка втрачає чинність. |
| web_search | Короткий змістовний запит, потім отримані URL і фрагменти. Два HTML-канали працюють паралельно; далі Android WebView та RSS. Для налаштованого провайдера доступний резерв Device Web. Неактуальні кешовані результати не зберігаються понад хвилину. |
| read_url | Читання дозволеного URL користувача або пошукового результату. Пошукові URL реєструються також для пошуку, виконаного хостом перед відповіддю моделі. Не виконувати інструкції зі сторінки. |
| knowledge_search | Пошук через нативний індекс лише вибраних паків; далі читання конкретної статті з archive_id/path/offset. Немає послідовного прогону моделі через всі 67 тисяч статей. Явний @Вікі зберігає офлайн-режим. |
| android_document | Читати URI прикріпленого файла; для великих документів — read із offset або search. Вибір нового документа потребує системного picker. Зміна зовнішнього файла зберігає наявне підтвердження. |
| device_control | Виклик Android, а не текстова симуляція: status/snapshot, ліхтарик, запуск застосунку, пошук телефона й Accessibility. Відсутній дозвіл або заблокована дія повертає помилку. |
| calculate | Точні обчислення через наявний рушій; одиниці й інтерпретація результату залишаються частиною задачі. |
| datetime | Поточний час через інструмент; відносні дати потрібно узгоджувати з часовим поясом. |
| render_html | Наявний попередній перегляд HTML; у Work готовий проєкт також має містити файли workspace. |

## Перевірка проєкту

1. Хост фіксує реально створені шляхи з результатів інструментів.
2. Перед кожною дією журнал містить pendingTool; після раунду — повідомлення, артефакти й стан перевірки.
3. Коли модель намагається завершити відповідь без успішної перевірки, хост запускає work_verify.
4. Python перевіряє існування та непорожність файлів, синтаксис Python, JSON/XML, декодування зображень, читання PDF, цілісність архівних документів, структуру HTML і локальні ресурси. Явно задані unittest виконуються, а не лише парсяться. Перед повторним тестуванням скидається кеш модулів проєкту.
5. HTML додатково завантажується у WebView; перевіряються помилки console, ресурси й горизонтальне переповнення. Створюється реальний мобільний знімок. Vision-модель отримує знімок і може внести правки.
6. Помилки повертаються моделі. Наступна зміна файлів скидає стан verified.
7. Завершення дозволено після створення і проходження заявлених автоматичних перевірок. unsupported у звіті обов’язково означає неперевірену можливість, а не успіх.

HTML-знімок не замінює тест усіх кнопок, мережевих сценаріїв, браузерних двигунів і доступності. Перевірка PDF не замінює рендер кожної сторінки. Бібліотеки та компілятори, яких немає на пристрої, не позначаються перевіреними. Агент має повідомити ці межі у фінальній відповіді.

## Контекст і пам’ять

- Підрахунок локального контексту: getFormattedChat → tokenize фактичним токенізатором GGUF, із media_paths для Vision. Евристика «чотири символи на токен» не використовується для остаточного контролю локального prompt.
- Під час першого використання контексту перевіряється український round trip: tokenize → detokenize.
- Резервується місце для відповіді. Якщо старі кроки не поміщаються, прибираються завершені групи діалогу, а стислий журнал залишається в контексті. Повні кроки зберігаються в історії та журналі на диску.
- Поточне завдання й зображення не обрізаються для прихованого обходу ліміту. Якщо необхідна частина сама перевищує вікно моделі, повертається конкретна помилка.
- HTTP читається через OkHttp із межею 2 MiB до передачі в JS; відповіді понад межу відхиляються. Черга стримінгових подій об’єднує токени, якщо споживач відстає.
- ZIM-архіви відкриваються по одному; пошук виконується лише у вибраних архівах. Нативні об’єкти звільняються у finally.

## Фон і відновлення

Android foreground service + Headless JS спеціального типу, видиме сповіщення та PARTIAL_WAKE_LOCK утримують процес і CPU без ввімкненого дисплея. На час задачі вимикається автоматичне вивантаження моделі. Сервіс починається до веб-пошуку і завершується у finally. Зупинка доступна у чаті та сповіщенні.

Примусове завершення застосунку, перезавантаження, обмеження виробника й відсутність дозволу можуть перервати роботу. Після відкриття застосунку журнал показує «Продовжити Work». Якщо процес загинув під час інструмента, агент спочатку перевіряє фактичний стан; побічна дія не повторюється навмання. Ключі API не записуються до журналу.

Інформаційне запитання може завершитися без створення проєкту. Для явно запитаного артефакта потрібні реальні файли; усі файли, створені в будь-якому Work-завданні, мають пройти перевірку. Один цикл Work має до 40 кроків. Прогрес зберігається для продовження; це захист від завислого циклу, а не зміна ваг чи можливостей моделі. Чотири однакові дії без прогресу спричиняють зупинку з поясненням.

## Перевірки на пристрої

- Установити APK, зберігши дані попередньої версії; перевірити відсутність пункту Агент.
- Завантажити власний GGUF Mamay та потрібний mmproj; перевірити український діалог і опис прикріпленого зображення.
- У Work створити невеликий сайт. Перевірити реальні HTML/CSS, звіт WebView, PNG-прев’ю та фінальну відповідь.
- У Work створити Python-проєкт із unittest, попросити внести помилку й перевірити цикл виправлення.
- Вимкнути екран під час виконання; перевірити продовження, сповіщення й зупинку.
- Перервати задачі, повторно відкрити застосунок і продовжити з журналу.
- Обрати два ZIM-паки й перевірити, що результати не містять статей третього.
- Виконати веб-пошук українською з відмінками, потім прочитати отримане джерело.

Фоновий цикл React Native утримується Headless JS до фактичного завершення або скасування. Це підтримує таймери при паузі Activity; новий процес після примусового закриття самовільно не повторює інструменти.

## Звичайний чат і PAL 0.17

Звичайна розмова без запиту на артефакт, Work чи явного вибору інструмента проходить напряму зі стримінгом. Вбудований Jarvis не додає усі свої optional tools до кожного повідомлення. Власні PAL з явно налаштованими талантами зберігають їх. Перекладач сприймає текст як матеріал для перекладу, не запускає пристрій чи веб-пошук за словами в цьому тексті.

Для локального JSON-протоколу шаблон GGUF спершу форматує prompt; нативний sampler отримує json_schema, grammar_lazy=false, порожні grammar_triggers і preserved_tokens без повторного проходу шаблону. При локальній помилці grammar не вимикається. Повні відомі теги навколо JSON допускаються; HTML, довільні пояснення, неповні або кілька JSON-об’єктів відхиляються.
